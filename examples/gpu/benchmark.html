Data is warmed first, so this measures URL parsing + rasterisation + transfer, not the network. The CPU path spreads across the worker pool; the GPU path renders sequentially on one context.

Parity: CPU tile vs GPU tile

Expected: sub-pixel float differences (fp32 vs fp64) and band edges quantised to the 2048-texel LUT on non-blended scales. On projected grids (LCC) the fp32 projection maths flips more band-edge pixels and the domain outline shifts by up to one pixel.

The map above is interactive: pick a backend and zoom/pan frantically yourself. The scripted sequence sweeps the zoom between 1 and 16 every 2 s while panning for 8 s, then waits for the map to go idle. The camera path is a function of wall time, so both backends follow the same path; a blocked main thread shows up as fewer frames and longer gaps, and tiles requested for zoom levels the camera has already left show up as aborts.
